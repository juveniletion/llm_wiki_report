> ⭐ **专为冷启动的摄入 agent 编写**——它没有记忆，只看本文件就该知道文件该叫什么、放哪、链接怎么写。

## 一、主题选择决策表

新内容该进哪个 `wiki/<topic>/`？按下表**从上往下**匹配，命中第一条即停。

| 优先 | topic | 骨架 | 命中条件 | 典型内容 |
|:-:|:---|:-:|:---|:---|
| 1 | `interfaces/` | G | 内容是**接口/契约/字段映射** | RPA 接口文档、报告模板占位符、API 规范 |
| 2 | `benchmarking/` | F | 内容是**两个及以上主体的横向对比** | 一厂 vs 二厂、本厂 vs 行业 |
| 3 | `gmp/` | E | 内容是**法规条款**及其成本关联 | GMP、药典、质量标准 |
| 4 | `equipment/` | C | 内容是**设备**（台账/折旧/维修） | 车间设备清单、维修记录 |
| 5 | `products/` | A | 内容主体是**某个具体产品** | 配方、工艺路线、单产品物料构成 |
| 6 | `market/` | D | 内容是**外部参照系**（行情/行业基准） | 药材价格、行业分位数据 |
| 7 | `costs/` | B' | 内容是**关于成本的知识**（口径/基线/机制） | 成本数据口径、异动登记册 |
| 8 | — | — | 以上都不匹配 | **停下来问人类**，或暂放 `raw/docs/` 不编译 |

### ⚠️ 三个最容易分错的边界

**1. 「产品工艺」vs「成本」**
- 讲**某个产品的**处方/工艺/物料 → `products/`
- 讲**跨产品**的成本口径/机制 → `costs/`

**2. 「成本」vs「归档」** ⭐
- `costs/` 存**关于成本的知识**（口径定义、基线、异动机制）
- **逐月成本分析报告属 `Query → Archive`，不入 `costs/`**
- 判据：这份内容回答的是"成本**是什么样**"（知识）还是"**这个月**成本是多少"（求值）？

**3. 「对标」vs「行情」**
- **两个主体的对比** → `benchmarking/`
- **单一外部数据源** → `market/`

## 一·五、页面粒度：实体页，不是批次页 ⭐⭐

> **本库犯过这个错**：摄入 2026-08 成本后新建了 `7-8月增量数据.md`。
> 那是**批次页**，违反了本库设计。已删除，内容并入 `三产品成本基线.md`。

**核心原则**：wiki 是**累积的实体页**，新数据要**长进**已有页面，
而不是在它旁边另起一页。页面变厚是正确演化；页面变多是病灶。

| 新内容 | 正确处理 |
|:---|:---|
| 已有实体的**新一期数据** | **并入**该实体页（表格加行、`信息截点` 推进） |
| 已有实体的**新发现/新冲突** | **并入** + `Status` 块 |
| 已有实体**旧结论被推翻** | **并入** + 限定/改写措辞 |
| "这一批摄入了什么" | → `log.md`（**不是** wiki 页面） |
| **全新实体**（wiki 中从未有） | 新建页 |

**一次摄入通常改多个页面**，四个动作见 `SKILL.md` 第四节 4.2。

## 二、文件命名

### 2.1 wiki 词条

| 规则 | 说明 |
|:---|:---|
| **用实体/概念名** | 文件名叫"这个概念是什么"，不叫"什么时候发生的" |
| **禁日期前缀** | ❌ `2026-05-金银花超支.md`（那是 log 的活） |
| **禁批次名** | ❌ `7-8月增量数据.md`（见第一·五节） |
| **禁时间范围** | ❌ `三产品成本基线（2026年1-6月）.md`——时间范围会随累积失效，放元数据 `信息截点` |
| **一层目录** | `wiki/<topic>/<article>.md`，**不得更深** |
| **同 topic 风格一致** | 本库统一用**中文概念名**（便于人类阅读与赛题交付） |
| **合法字符** | 不得含 `/ \ : * ? " < > \|` 与换行 |

✅ 好例子：`成本异动登记册.md`、`三产品成本基线.md`、`RPA接口契约.md`
❌ 坏例子：`2026-05-金银花超支.md`、`7-8月增量数据.md`、`三产品成本基线（2026年1-6月）.md`、`新文档.md`

### 2.2 raw 文件

| 规则 | 说明 |
|:---|:---|
| **保持原名** | 采集时尽量保留源文件名（便于人类辨认出处） |
| **同名追加后缀** | 已存在则加 `-2`、`-3`，**绝不得覆盖** |
| **禁止改名** | 已入库的 raw **不得为了"规范"而重命名**——会切断所有 `Raw:` 回链 |
| **派生缓存同名** | `x.docx` 的派生文本是 `x.txt`（仅换后缀） |

## 三、链接约定 ⭐⭐

> **这一节曾经出过真实事故**：批量补链接时把 `../raw/`（一级）写成了正确的
> `../../raw/`（二级），一次制造 7 个死链。**务必按下表，不要凭感觉。**

### 3.1 链接深度对照表

起点不同，相对深度**不同**。先确认"我是从哪个文件出发的"。

| 起点（当前文件） | 目标 | 写法 | 说明 |
|:---|:---|:---|:---|
| `wiki/<topic>/<article>.md` | 某个 raw 文件 | `../../raw/<sub>/<file>` | **两级**：topic → wiki → 根 |
| `wiki/<topic>/<article>.md` | 同 topic 另一词条 | `./<other>.md` 或 `<other>.md` | 同级 |
| `wiki/<topic>/<article>.md` | 跨 topic 词条 | `../<other-topic>/<other>.md` | **一级** |
| `wiki/<topic>/<article>.md` | 索引 / 日志 | `../index.md` / `../log.md` | **一级** |
| `wiki/index.md` 或 `wiki/log.md` | 某个词条 | `./<topic>/<article>.md` | 同级 |
| `wiki/index.md` 或 `wiki/log.md` | 某个 raw 文件 | `../raw/<sub>/<file>` | **一级** |
| `README.md`（根） | wiki / raw | `./wiki/...` / `./raw/...` | 同级 |

**记忆法**：数"从当前文件往上走几层才到 `pharma-cost-wiki/`"。
`wiki/products/银黄口服液.md` 要上 **2** 层（product → wiki → root），所以 raw 链接是 `../../raw/`。

### 3.2 行内证据坐标（与链接并存）

链接是**文件级**的；坐标是**行内、逐数值**的定位。两者同时存在，缺一不可。

| 源类型 | 坐标格式 | 示例 |
|:---|:---|:---|
| CSV | `[文件名.csv:列名:筛选条件]` | `[中药一厂_成本汇总_2026年1-6月.csv:单位成本(元/盒):银黄口服液&2026-05]` |
| PDF | `[文件名.pdf:P页码:章节名]` | `[产品配方文档_银黄口服液.pdf:P2:单盒材料成本参考]` |
| Python | `[文件名.py:函数名]` | `[mock_rpa_server.py:create_task]` |
| 跨文件 | `[文件A.csv:列X] + [文件B.pdf:P页码]` | 采购价与配方用量关联时 |

坐标写在**数值所在行或句末**，用反引号包裹。

### 3.3 词条头的 `Raw` 字段

**必须列出该文用到的全部 raw 文件**，分号分隔：

```markdown
> Raw: [文件A.csv](../../raw/csv/cost_data/文件A.csv); [文件B.pdf](../../raw/pdf/pharma_docs/文件B.pdf)
```

> ⚠️ 常见错误：正文用坐标引用了某文件，但 `Raw` 字段忘了列它。
> 这会让 `check_evidence.py` 报"证据错误"——因为它不知道去哪儿找这个字面量。
> **写完全文后回头核一遍：正文出现过的每个文件名，Raw 字段里都要有。**

### 3.4 对话输出 vs 文件内链接

| 场景 | 用哪种 |
|:---|:---|
| **wiki 文件内部** | 相对当前文件的路径（按 3.1 表） |
| **对话输出给人类** | 项目根相对路径，如 `wiki/costs/成本异动登记册.md` |

## 四、元数据字段

### 4.1 词条（每篇必填）

```markdown
# {标题}

> 所属分类: <大类> / <子类>
> 实体类型: <公司|产品|数据集|概念|分析|法规|契约|设备资产>
> 信息截点: <YYYY-MM-DD 或 YYYY-MM>（内容对应的事实截止日）
> 信源摘要: <文档名>, <版本>, <日期>
> Raw: [文件](../../raw/<sub>/<文件>); ...
> 最后编译: <YYYY-MM-DD>
```

| 字段 | 要点 |
|:---|:---|
| `信息截点` | 取自来源的**事实截止日**，不是今天 |
| `最后编译` | **知识内容**最后变化的日期。改错别字、调格式、修链接 —— **不刷新** |
| `Raw` | 见 3.3，必须完整 |

### 4.2 归档页（`Query → Archive` 的产物）

```markdown
> 引用: [{被引词条}](../<topic>/<词条>.md)
> 归档: <YYYY-MM-DD>
```

- **无 `Raw` 字段**（内容来自综合问答，不是 raw 材料）
- **永不参与级联更新**（是时间点快照）
- 在 `index.md` 中的摘要前加 `[Archived]`

## 五、日志条目格式

追加到 `wiki/log.md`，**只追加不修改**。

### ingest（有新知识产出）

```markdown
## [YYYY-MM-DD] ingest | <主词条标题>
- Disposition: <New; Update; Disputed>
- Raw: raw/<topic>/<file>
- Updated: <被级联更新的词条标题>
```

无级联更新时省略 `- Updated:` 行。

### ingest（无新知识）⭐

```markdown
## [YYYY-MM-DD] ingest | no material: raw/<topic>/<file>
- Disposition: No material
```

> ⚠️ **`ingest | no material:` 的措辞不得改动**——它是 `check_evidence.py` 的机器读取键，
> 用来排除"已声明无价值"的 raw 文件，避免误报为"未被引用"。

### lint

```markdown
## [YYYY-MM-DD] lint | <N> 个问题，自动修复 <M> 个
```

### Archive

```markdown
## [YYYY-MM-DD] query | Archived: <页标题>
```

## 六、Status 块

新源取代或矛盾已有断言时，**保留旧断言**，在其正下方加块：

```markdown
> **Status: Outdated** (YYYY-MM-DD)
> 什么变了、当前理解是什么、附坐标

> **Status: Disputed**
> - 信源A: {数值} [坐标]
> - 信源B: {数值} [坐标]
> - 工程判定: {采信哪方及理由}
```

| 类型 | 必填 |
|:---|:---|
| `Outdated` | **日期** + 当前理解 + 坐标 |
| `Disputed` | 各方主张 + 各自坐标 + **工程判定** |

缺任一项即为**畸形块**，Lint 须报。

> **永不静默删除或改写**已被推翻的断言。这是本库"历史不可篡改"原则的落点，
> 也是 human-in-the-loop 能成立的前提——审核者要知道历史没被改过。

## 七、快速自检清单

写完一篇词条后，对照勾选：

- [ ] 文件在 `wiki/<topic>/` 下，仅一层目录
- [ ] 文件名是概念名，无日期前缀
- [ ] 六个必填元数据齐全，`最后编译` 是今天
- [ ] `Raw` 字段列出了正文引用过的**全部** raw 文件
- [ ] 所有 raw 链接是 `../../raw/`（**两级**）
- [ ] 跨 topic 链接是 `../<topic>/`
- [ ] 每个关键数值旁有行内证据坐标
- [ ] 派生值展示了公式
- [ ] 冲突处有 `Status` 块（`Disputed` 含工程判定）
- [ ] `index.md` 已加条目
- [ ] `log.md` 已追加
- [ ] `python scripts/check_evidence.py .` 结构层为 0 错
