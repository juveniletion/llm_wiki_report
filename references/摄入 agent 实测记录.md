# 摄入 Agent 实测记录

> 记录日期: 2026-09-22
> 目的: 验证「独立 LLM 实例 + 规范驱动」的摄入与增量维护能力
> 结论: **通过**（详见下）

---

## 1. 为什么需要这个实测

本库的核心主张是：**规则外置成文件，agent 每次运行重读，因此"改规则"不用"改 agent"。**

在此之前，所有摄入都是由**人类（我）代劳**的——那验证不到"一个独立 LLM 能否按规范干活"。
本次实测把摄入交由**独立 LLM 实例**执行，人类全程不介入其推理与编辑。

---

## 2. 被测对象

| 组件 | 作用 |
|:---|:---|
| `scripts/ingest_raw.py` | 采集层（确定性）：格式转换、落位、去重、派生文本、找级联候选 |
| `scripts/ingest_tools.py` | 摄入工具集：`grep_raw`（先定位）、`patch_wiki_article`（并入）、`write_wiki_article`（新建，受守卫）|
| `scripts/ingest_agent.py` | 运行时：**每次从磁盘重读** `INGEST_AGENT.md` 等规范作系统提示 |
| `INGEST_AGENT.md` | 提示词：声明"无记忆，先读规范再动手" |

**关键设计**：规范不仅写在提示里，还**内建进工具**——
`write_wiki_article` 会拒绝批次页式命名。**提示可能被忽略，工具不会。**

测试文件由 `scripts/make_test_corpus.py` 生成，覆盖 7 种格式：

|:-:|:---|:---|:---|

## 4. 实测结果

### 4.1 采集层

| 指标 | 结果 |
|:---|:---|
| 采集成功率 | **8/8**，0 失败 |
| 去重 | 同一文件重复提交 → `skipped`（内容哈希） |
| 派生文本 | PDF/Word/Excel 均生成可 grep 的 `.txt` |
| 主题推断 | 8 个文件全部落位正确 |

**采集层暴露并修复的 3 个缺陷**：

| # | 缺陷 | 修复 |
|:-:|:---|:---|
| 1 | `.txt` 因正文含 "GMP/收率" 被错落到 `pdf/pharma_docs/` | 新增 `TOPIC_EXT_COMPAT` 目录↔扩展名相容性校验 |
| 2 | 修过头：`.xlsx` 成本汇总被拒于 `csv/cost_data/` 之外 | 放宽 `csv/*` 接受 xlsx/xls（该前缀表示"表格数据"而非格式） |
| 3 | `ensure_utf8_stdout` 非真幂等 | 增加对当前 stdout 类型的判断 |

### 4.2 编译层（独立 LLM 执行）

**工具调用轨迹**（共 86 次）：

```
34 × grep_raw              ← 先定位
33 × patch_wiki_article    ← 后书写（并入已有页）
10 × read_wiki_article
 3 × read_raw
 2 × run_evidence_check
 1 × list_wiki_articles / append_wiki_log
────────────────────────────
 0 × write_wiki_article    ← ⭐ 从未试图新建页面
```

**关键指标**：

- `write_wiki_article` **调用 0 次** → 未新建任何批次页
- 词条数 **12 → 12**（摄入前后不变）
- 校验器结构层 **0 错**（索引缺失/死链/证据错误/不可解析全为 0）

**产出一览（一次摄入改 5 个页面）**：

| 页面 | 变化 |
|:---|:---|
| `costs/三产品成本基线.md` | 三表加行 + 新增章节 |
| `products/银黄口服液.md` | 并入实测收率 `89.2%` |
| `equipment/设备台账与维修历史.md` | 新增设备事件节 |
| `market/药材行情与行业基准.md` | 新增行情节 |
| `costs/成本异动登记册.md` | 归因准则新增 2 行 |
| `index.md` | 摘要 + 问题计数同步 |

**"重新组织既有表述"**（增量维护中最难的一步，agent 做到了）：

- 原"**raw 中尚无实际收率数据**" → 改为"**实测 `89.2%` 已达标，但降本仍未显现**"
- 原"维修历史全部 **4** 条" → **5** 条；"2026 年只有一条" → 限定为"**上半年**"
- 新增准则：**收率达标 ≠ 成本下降**；**计划性维护 ≠ 故障**

### 4.3 独立核验（不采信 agent 自述）

| 核验项 | 结果 |
|:---|:---|
| 词条数未增加 | ✓ 12 → 12 |
| 无批次页文件 | ✓ |
| 校验器结构层 | ✓ 0 错 |
| 自述的 6 处编辑真落盘 | ✓ 逐条验证 |
| 7 个关键数字在 raw 可定位 | ✓ 全部命中 |
| 4 个环比复算 | ✓ 全部一致 |

**发现的 1 个缺陷**：设备词条出现重复的 `### 2.2` 编号（应为 2.3）。已修。

---

## 5. 结论

1. **规范驱动有效**：agent 在零记忆的前提下，仅凭磁盘上的规范完成了分诊、编译、级联、收尾。
2. **实体页纪律成立**：`write_wiki_article` 零调用，33 次编辑全部是 `patch`（并入）。
3. **"先定位后书写"被实际执行**：34 次 `grep_raw` 发生在任何写入之前。
4. **冲突检测有效**：`Disputed` 块被正确创建，且**冲突两侧都标**。

> ⭐ **最有价值的观察**：agent 主动完成了"重新组织既有表述"——
> 它没有简单追加，而是**改写了因新数据而失效的旧结论**（"无收率数据"→"已达标但降本未显现"）。
> 这是"增量维护"与"堆积"的分水岭。

## 6. 痕迹与回滚

**本次实测产生的测试数据（8 个文件 + 相应词条改动）已从 `main` 回滚**，
`main` 分支只保留**方法与规则**：

- `scripts/ingest_agent.py`、`scripts/ingest_tools.py`（agent 运行时与工具）
- `SKILL.md`、`INGEST_AGENT.md`、`references/命名与链接约定.md`（规范补强）

**测试的完整痕迹保留在分支 `test-archive`**（原 `test/llm-wiki-ingest-battery`），
包含：测试脚本、虚拟文档、agent 的全部产出、以及实测后的 wiki 状态。

**查看方式**：

```bash
git log --oneline test-archive                    # 看测试提交序列
git diff main test-archive --stat                 # 看测试引入了哪些改动
git show test-archive:project-report-agent/llm-wiki/pharma-cost-wiki/wiki/index.md   # 看测试后的索引
```

**复现实测**（在测试分支上）：

```bash
python scripts/make_test_corpus.py testcorpus     # 生成虚拟文档
cp testcorpus/* inbox/                            # 投放到 inbox
python scripts/ingest_agent.py --inbox            # 独立 LLM 执行摄入
```

## 7. 已知限制

1. **无长期记忆是设计而非缺陷**，但意味着：**它不会记住上次的教训**。
   所有约束必须写进规范或工具，不能依赖 agent"记得"。
2. **测试只覆盖了单一轮次**。多轮连续摄入（如连续 3 个月数据）下的累积行为未经测试。
3. **`表格型 Excel 的数值精度**：单元格存的 `141` 与显示的 `141.0` 不同，
   派生文本按单元格值输出。这不是精度损失，但需知悉。
4. **PDF 复杂表格仍可能串列**。冲突时以 PDF 权威件为准。
